# Autonomous Software Engineering System — Architecture Plan

**Status:** Architecture agreed. Ready to implement Phase 0.

---

## Context

A prior attempt at this system collapsed under accumulated complexity: it advanced through layers before earlier layers were validated, and built abstractions to serve requirements that had not yet been discovered. We are resetting to the architecture stage.

The goal is a durable platform in which LLM agents are **replaceable, sandboxed, permissioned workers** producing **validated artifacts** under **deterministic orchestration**. Truth lives in a control plane, never in prompts or agent-to-agent conversation.

The handoff proposed a 20-stage sequence. That sequence is a waterfall which repeats the original failure in a new form — building infrastructure against imagined requirements. Its first real output lands around stage 10, meaning stages 1–6 design abstractions to serve requirements discovered in stages 7–15. This plan inverts it: the agent does real work in week 3, and every platform layer is built only after the pain it solves has been measured.

**The product is a collision-risk quantification system for autonomous vehicles** — computing risk metrics from AV simulation output and real deployment data, sold to companies that need to quantify collision risk. This product choice is unusually well suited to the factory, for reasons detailed below.

---

## Reality anchor

No production system today autonomously produces enterprise SaaS. What is actually demonstrated:

- SWE-bench Verified scores of 70–80% are for **localized bug fixes in existing repos where a failing test is supplied in advance**. Ground truth is external and pre-existing.
- Coding agents are strong at bounded brownfield tasks under human review. Unsupervised merge rates on real production PRs are substantially lower and rarely published.
- Greenfield multi-service SaaS built end-to-end without human intervention: no production evidence exists.

Therefore the target is a **supervised software factory with shrinking human gates**, where autonomy is granted per task-class based on measured merge rate and defect-escape rate — not declared at the end of a stage list.

---

## The organizing principle

Every major decision below reduces to one rule:

> **Agent autonomy tracks the availability of ground truth the agent did not author and cannot retrieve.** (amended by A8)

Where an independent check exists, the agent may work and may eventually work unattended. Where it does not, the work is human-owned. This single rule generates the task model, the protected-path rules, the criterion-provenance ladder, and the autonomy-graduation gates. It is also a mechanical test applicable to any new task: *what independent thing says this is right?* No answer means it is not agent work yet.

## Decisions

| # | Decision | Rationale |
|---|---|---|
| 1 | **Real product with real users** is the first deliverable; the factory is a byproduct. | Real usage supplies ground truth. Without it, validation stays synthetic and the platform is built against imagined requirements — the original failure mode. |
| 2 | Product is **backend/data-heavy** with thin UI. | Correctness must be machine-checkable. UI-led products have no automated verdict, making evaluation and self-improvement structurally impossible. |
| 3 | **Human hand-builds the initial skeleton** — repo, schema, CI, deploy, first metrics, initial test suite. | Greenfield is where agents are weakest; every credible result is brownfield. This places the system on the part of the capability curve with evidence behind it. |
| 4 | **A task is only schedulable if it carries an executable acceptance criterion.** Prose-only tasks are unschedulable and escalate. | This is the mechanism behind SWE-bench-level performance. Remove it and measured performance collapses. |
| 5 | **The harness executes checks, never the agent.** Agent output is a *claim*; the harness produces the *fact*, on a clean checkout, written to an append-only evidence store. | If the agent self-reports results, the entire validation system is theatre. |
| 6 | Criteria start **human-authored**, graduating to **agent-authored** per task-class once calibrated against paired data. | Human-authored tasks generate the evidence needed to prove agent-authored criteria are equivalent. There is no way to skip this and still have evidence. |
| 7 | The adversary is **deterministic tooling, not a second LLM**: Hypothesis property tests primary, mutmut secondary. | Properties encode intent over generated inputs; the agent cannot special-case past inputs it never sees. Mutation score measures branch coverage only. An LLM adversary is reserved for what neither reaches: missing requirements. |
| 8 | Capacity: **20+ hrs/week sustained.** | Enough for platform and product in parallel. Does not remove the obligation to build one capability at a time. |
| 9 | **Buy the agent loop and sandbox; build the control and evidence planes.** Claude Agent SDK behind a `Worker` interface; Docker container per task. | Rebuilding solved infrastructure is how the prior attempt consumed its hours. |
| 10 | **Hard blast-radius separation.** Ephemeral container, throwaway DB from migrations, no production credentials in context, output is a PR only. Deploy stays CI-triggered on merge. | Worst case from a fully compromised agent is a pull request that gets declined. |
| 11 | **Protected paths are harness-enforced**, defined by ground-truth provenance (see below). | Otherwise the agent can make checks pass by deleting them — a standard reward-hacking outcome, not a hypothetical. |
| 12 | **Network deny-by-default with allowlist** in the sandbox. | Everything the agent reads (issue text, dependency READMEs, error messages, web content) is attacker-reachable and enters its context. Egress control caps damage even when injection succeeds. |
| 13 | **Python throughout.** `uv`, `ruff`, `pytest` + `hypothesis`, `pyright --strict`, FastAPI + Pydantic, Alembic, Postgres, Docker. | Single toolchain. Pydantic gives executable contracts. Hypothesis is the strongest available adversary. numpy/scipy is correct for the domain. |
| 14 | **Batch replay first; streaming later.** Phase 0 ingests a scenario log and returns metrics deterministically. | The replay harness is permanent infrastructure — it is how streaming gets validated, how agent changes get scored, and how customer-reported discrepancies get reproduced. Building it first is not a detour. |
| 15 | **LangGraph as the graph engine**, with Pydantic state schemas and the Postgres checkpointer. | Battle-tested implementation of typed channels, reducers, and conditional edges. Adopting the model directly avoids designing it from scratch. |
| 16 | **Verdict fields are owned by deterministic nodes.** Agent nodes are schema-forbidden from writing them. Evidence lives in Postgres tables, not in graph state. | Resolves the conflict between LangGraph's node-returns-state-update model and decision 5, inside LangGraph's own ownership model rather than fighting it. |
| 17 | **The full ~55-document register is written before Phase 0 code**, with mandatory status headers, declared evidence basis, and falsification conditions. | Chosen with the waterfall risk explicit. Writing the documents is not the hazard; believing them is. The header contract converts pre-evidence documents from assumptions into scored predictions. |
| 18 | **Agents are capability-scoped, never role-scoped.** An agent is `(input contract, output contract, tools, permissions, criteria, escalation)` — never a job title. | A role has no input/output contract, therefore no golden tasks and no measurable merge rate. Role-based agents structurally break the Phase 4 autonomy mechanism. Agents also must justify themselves against a deterministic alternative: open input space and checkable output, or it is a node. |
| 19 | **Autonomy grants are keyed to a fingerprint** — `(capability, model_version, prompt_version, tool_version, context_strategy_version)`. Any change suspends the grant until re-measured, tiered: smoke subset for prompt/context changes, full golden set for model or tool changes. | Every measurement describes a specific system. Model deprecation is scheduled by the provider, not by you — without standing re-qualification, every grant eventually rests on a model that can no longer be run. Fingerprint tracking must therefore exist from Phase 2, not Phase 4. |
| 20 | **Agents may improve the factory, never the inspector.** Permanently protected: `CriterionRunner`, `EvidenceStore`, `PolicyEngine`, `AutonomyGate`, protected-path config, sandbox spec, fingerprint tracker. | Every safeguard here assumes the judge is independent of the worker. An agent editing the judge collapses all of them at once, silently, with tests green — because the tests are downstream of the edit. This is ordinary optimization pressure, not malice: "make the criterion runner faster" that quietly loosens a tolerance looks like success at every layer of observation available. |
| 21 | **Alfred designs multi-product, builds single-product.** Domain behind ports, real tenancy, per-product policy — but no second product until the first has paying users, and no platform sales. | Forward-compatible at near-zero cost since the invariants already require tenancy. The gate is revenue, not readiness, because "the platform is ready for a second product" is a judgment the platform will always make in its own favour. |
| 22 | **Review is criterion-first, diff on signal.** Reviewer reads intent → criterion → evidence bundle → diff summary; full diff only when something looks wrong. Review time is recorded as a task-size signal. | If the harness verified correctness, a human reading the diff for bugs duplicates the harness — and that duplication is where review fatigue comes from. The human checks what the harness structurally cannot: whether the criterion was the right criterion, whether the agent solved the stated problem or a nearby easier one, future coupling cost, and whether a metric's validity envelope is honestly stated. |
| 23 | **Escalation triggers are structural, not agent-judged.** Iteration cap, budget exhaustion, criterion red after N attempts, protected-path attempt, tool unavailable. Agent-initiated escalation is permitted as a budget optimization but never load-bearing. Agent cannot write `blocked` or `complete`. Every escalation carries a structured attempt bundle. | Agents almost never stop — default behavior under an unsatisfiable task is a plausible partial solution, not an admission. Escalation therefore cannot depend on the agent recognizing it is stuck, since that is precisely the judgment the failure compromises. An agent that can declare itself blocked can also declare itself done. |
| 24 | **One criterion = one task.** Agents may create subtasks freely, each receiving its own budget allocation. | Chosen for throughput and to let decomposition scale without human involvement. **Known exposure, accepted:** budget ceilings become advisory, since an agent approaching its cap can split into subtasks that each receive fresh budget. No malice is required — it is the locally rational move under a constraint. A global tree cap would have preserved the same agent freedom while bounding total spend; the absence of a stop is the deliberate trade. Logged in the Risk Register with revisit trigger: first observed decomposition tree exceeding expected spend by 5×. |
| 25 | **Org-level hard spend ceiling; cost-per-merged-task is a first-class metric.** No per-task ceiling. Dispatch halts at a monthly org limit, with real-time alarms. Cost recorded per run, per node, per capability from Phase 2. | Cost as a bill is bookkeeping; cost-per-merged-task is what makes capabilities and models comparable. Merge rate alone ranks a 90%/$50 capability above a 60%/$3 one, which is backwards. An autonomy grant must therefore read "X% merge, $Y per success, on fingerprint Z" — all three. Attribution cannot be applied retroactively, so it must exist before it is needed. |
| 26 | **Context = deterministic seed + free agent search + full read-recording.** Harness seeds (task, criterion, conventions, protected paths, prior artifacts); agent searches freely in the sandbox; every file read and search issued is recorded to the evidence store as the run's observed context. | Agentic retrieval is why agents work, but it is nondeterministic — which appears to break decision 19's fingerprint. Recording resolves it: reproducibility comes from the evidence store, not from constraining retrieval. Runs replay against the exact file set they saw. Side benefits: context becomes measurable (which reads correlate with success), and the read log is a *partial* forensic trail after an injection incident — **downgraded 2026-08-15, and the downgrade is the honest form of the original claim.** Completeness is demonstrated only against the executor's own durable event count (containment assertion C1), which proves no event was lost between the executor and the store and **cannot prove an event was emitted for everything the agent did**; the log's granularity is the action, not the file read, so files opened inside a shell command are recorded as one command. The log is therefore **positive evidence** — content it records did enter context, which suffices to identify a payload that arrived through a recorded read and to compute retrieval miss rate — and **not negative evidence**: the absence of a read from the log is not evidence the read did not happen. What bounds the set of bytes that could have been read is the asserted mount set (C9, C12), not the log, and that bound is the stronger forensic object in the direction an incident actually asks about. An independent observation channel — filesystem-level read auditing inside the container — was considered and **rejected on containment cost rather than effort**: the kernel audit subsystem is not namespaced and fanotify/eBPF attachment requires capabilities the sandbox must not hold, so completing the trail would mean enlarging the privilege set of the thing the trail exists to bound. Revisit if runs ever execute on a Linux host Alfred owns, where a host-side watcher sits outside the container's capability set. Read-recording must be in the `Worker` port from Phase 1 regardless — the downgrade is to what the log proves, never to whether it is kept. |
| 27 | **Result provenance, recall protocol, and published validity envelopes — all in Phase 0.** Every emitted result carries metric version, code commit, assumption set, input hash, and tolerance. Defects trigger a versioned advisory naming affected versions and date ranges. Each metric ships a validity envelope in its model card. | A wrong risk number is not an outage: it does not throw, spike latency, or fail a healthcheck. Every observability mechanism in this plan detects a different class of failure. Remediation therefore has to carry the load, and remediation needs stamping that **cannot be retrofitted** — results computed before it exists are permanently unrecallable. The advisory model works without holding customer data, so it stays compatible with a customer-deployed product. |
| 28 | **Stage gates are executable where measurable; overriding one requires an immutable waiver ADR** recording gate, threshold, actual value, reason, and the condition that would reverse it. | Every forbidden-advancement condition in this plan is a promise made to a future self who will be under pressure and will want to proceed. A gate that can be waived silently is a note, not a gate — but an unwaivable gate gets bypassed entirely rather than adjusted honestly. Making the override expensive and permanent is the realistic control. Waiver count becomes its own health metric. Note this is the only control in the architecture aimed at the human rather than the agents, and it addresses the failure that actually occurred last time. |
| 29 | **Golden tasks pin the parent commit; the set is stratified and accumulates continuously.** Successes, failures, near-misses and escalations all enter. Every comparison reports its detectable effect size. | Three traps. (a) A set built from successes reads ~100% forever and goes green through changes that break everything else — the failures are the informative half. (b) Once a fix is merged the task is trivial, so tasks must run against the parent tree, not HEAD; this is why SWE-bench is constructed that way. (c) At n=20 and p≈0.6 the standard error is roughly 11pp, so an observed 10pp gain is noise; resolving ~5pp needs roughly 150–400 tasks. **The Phase 1 twenty and the regression set are therefore two different artifacts** — twenty is ample for a failure taxonomy and useless for comparing configurations. Decision 19's tiered re-qualification depends on this distinction. |
| 30 | **The product is a re-derivability layer for computed criticality metrics** — not a risk oracle, and not an attestation service. What K5 removed was the claim that someone is *compelled* to procure an independent opinion — a market claim fused into a product decision and therefore never separately tested. The word "audit" carried the fusion: re-derivability is a property of the artifact and needs no buyer's compulsion; attestation is a service needing both compulsion and an attester with standing. Alfred builds the first. Original rationale, still standing on its product half: incumbents already own coverage and dashboards — Applied Intuition sells the aggregation-and-validation layer to 18 of the top 20 OEMs; Foretellix authors the ASAM standard; Streetscope has a published method and an ISO 26262 application. Meanwhile the differentiator Alfred was counting on — absolute risk quantification — is exactly what surrogate metrics cannot deliver: TTC and PET produce contradictory conclusions on identical data, and no threshold standard exists. Reproducibility is ~~unclaimed, is the audit need behind "independent evidence for the system safety case", and~~ **[clause withdrawn 2026-08-14; replaced 2026-08-15 after research — reproducibility is not "unclaimed": SSP-LS-Traceability 1.0.0 already specifies the record (SHA3-256 checksum, generating tool, derivation chain) and prostep ivip is funded to pursue it. | 31 | **LLM judge admitted as an advisory signal only.** It may raise escalation and flag suspected reward hacking; it is schema-forbidden from writing any verdict field. It is treated as a capability with golden tasks, a measured false-escalation rate, and its own fingerprint. | EvilGenie found LLM judges outperformed held-out tests at reward-hack detection (0 FP / 0 FN across three models) with "only minimal improvement from the use of held out test cases" — so decision 7's original exclusion was a determinism preference presented as an efficacy claim. | 49 | **A grading point is admitted by the provenance of its authorship, not by whether the oracle happened to ship a second constant.** Five tiers: **P1** second pinned oracle constant · **P2** oracle-pinned equivariance relation · **P3** oracle recomputation on a seeded resampled slice (= A8's existing mechanism) · **P4** invariance property over inputs generated at verdict time · **P5** held-out degeneracy case from the edge-case catalog. Every schedulable task carries **≥2 grading points, ≥1 held out**, and **≥1 level-fixing point from P1–P3**. P4 alone is invalid — invariance fixes a result's *shape*, never its *level*, so a uniformly scaled wrong answer satisfies it. The held-out point's tier is recorded with every verdict and merge rate is reported stratified by it. | The 2026-08-13 enumeration graded task admissibility by counting pinned constants, which is a proxy for what A3/D33 actually need: **a visible/held-out split where passing the visible half does not imply passing the held-out half.** The proxy is wrong in both directions. **Too loose** — of the 10 "strong" measures only **7** hold two independent literals; three derive their second value relationally from the first *computed* value (`thw - 10*dt`, `wttr + 1.0`, `ttce2 - 10*dt`), so a stub that gets the first value wrong gets the second consistently wrong and the pair tests one thing. **Too strict, and this is the larger error** — invariance under rigid transforms and time shifts, and the 30 degeneracy cases, are held-out points **authored by mathematics**: external, unretrievable, and unmemorisable from any constant. | 50 | **The oracle is absent from the execution plane by assertion, not by convention.** `commonroad-crime` and its transitive closure must be **unimportable inside the agent container**, asserted at sandbox boot beside the egress canary, and the assertion is fail-closed: a run that cannot demonstrate the oracle is absent does not start. | A8's rule is ground truth the agent *did not author* **and cannot retrieve**. The retrieval half has an implemented enforcement (held-out values behind a separate DB role) and an **unimplemented** one: the oracle itself. Grep found no occurrence of the oracle in `sandbox-specification.md`, `protected-paths-policy.md` or `definition-of-done.md`, and Phase 0 is specified to use CriMe as its oracle — so the import is coming and nothing in the register stops it landing in the agent tree. If it is importable, a wrapper delegating to `commonroad_crime` passes the published constants, **every P3 resampled perturbation** (the same code produced them) and **every P4/P5 invariance and degeneracy property** — with a clean transcript and no dishonesty anywhere in the loop. Merge rate would then measure delegation. **This blocks every option equally**, including running the 10 strong tasks unchanged, so it is not downstream of the exit-criterion choice — it is upstream of it. **Consequence if the assertion cannot be made to execute: every merge-rate figure measured to that point is void, not suspect.** **Amended 2026-08-15 (see D54) — the assertion is bounded, and the bound is part of the decision.** D50 as written implies the assertion closes retrieval. It closes four paths and leaves five open, named so no merge-rate figure is read as stronger than it is. *Closed:* the oracle as a declared or transitive dependency; the oracle present but unimported; a vendored copy retaining the module name, a stray `.pth`/`sitecustomize`, or a wheel in a resolver cache; acquisition during the run. *Open, and unclosable by this mechanism:* (a) **reconstruction from model weights** — if the oracle's source or published values sit in the lane's training data the agent reproduces them without importing anything, and this probe cannot measure that; (b) a **renamed, reformatted vendored copy** — the checks are name- and hash-based, never semantic, and a semantic check that worked would itself be an unvalidatable judgment inside the evidence plane; (c) **non-Python paths** — a shared object reached through `ctypes`, a subprocess binary, a data file of constants; (d) a **non-enumerable interpreter** — the probe cannot prove its own enumeration was complete, only fail closed when enumeration errors; (e) a **compromised runtime or base image**, already out of scope in the Threat Model and inherited rather than closed. ## Why this product fits the factory

**Ground truth is native.** Scenario logs have known outcomes. Replay the same log, get the same number — a deterministic regression harness, free, from day one.

**Numeric outputs make Hypothesis lethal.** Risk metrics have real assertable properties: bounded, monotone as time-to-collision decreases, invariant under coordinate-frame rotation and translation, well-defined in degenerate cases (stationary ego, parallel paths). An agent cannot special-case past generated trajectory families.

**The task tail is long and unusually well-shaped.** Each surrogate safety metric — TTC, MTTC, PET, DRAC, TTB, PRI, RSS-style formulations — is a *paper- or standard-specified, numerically verifiable, bounded* unit of work. Spec pre-exists; verification pre-exists (reproduce published values on a public dataset). This is close to the best agent task class available: SWE-bench-shaped, but producing real product value. Beyond metrics: scenario format parsers (ASAM OpenSCENARIO/OpenDRIVE), simulator integrations (CARLA, CarMaker, rFpro), sensor-log ingest, coordinate transforms, aggregation, reporting, API surface.

### Two risks specific to this product

**Safety-critical means a wrong number does not crash — it looks fine.** This is the "plausible but incorrect artifact" hazard in its most dangerous form. It is why decision 11's boundary matters more here than in a typical product: implementing TTC per its published definition against reference values is safe agent work; the proprietary risk formulation, its calibration and thresholds have no external check and are human-owned.

**User reachability is the weak spot.** AV companies are few, slow, and procurement-heavy; five real users may be months out, which starves decision 1 in the near term. Mitigation: **public datasets are the interim user.** nuScenes, Waymo Open Motion, Argoverse 2, CommonRoad, and the levelXdata drone sets (highD/inD/exiD) provide real trajectories with real outcomes and, for several metrics, published reference values — genuine *external* ground truth before any customer exists. Benchmark results against public datasets double as the distribution strategy into AV companies. **Action: identify three candidate design partners during Phases 0–1.**

## Architecture

```
CONTROL PLANE (deterministic; Postgres is the only source of truth)
  work items | acceptance criteria | protected paths | permissions | run history
        │ dispatches
        ▼
EXECUTION PLANE (isolated, disposable, untrusted)
  Alfred-owned Docker container: repo checkout + tools + OpenHands worker (pinned by commit SHA; local model)
        │ emits patch file to mounted volume (A2 — no VCS credential in container)
        ▼
EVIDENCE PLANE (append-only; written ONLY by the harness, never the agent)
  artifacts | check results | traces | diffs | wall-clock | latency | verdicts
        │
        ▼
GATE  patch-validation (protected paths, A10 scan) → criterion execution on clean checkout
      → held-out composed criteria → human review → merge → CI deploy
      (VcsGateway runs OUTSIDE the agent container)
```

**The load-bearing constraint is that the evidence plane is never written by the agent.** That single rule drives more of the architecture than the entire original stage list.

### Graph model

Nodes are units of work — agent nodes or deterministic nodes. Edges are transitions: sequential, conditional, fan-out, fan-in, loop-back. State travels the edges. Drift is prevented by four rules, all enforceable within LangGraph:

1. **One owning writer per field**, declared in the state schema. Fan-in on a shared field requires an explicit reducer (append / max / merge / first-wins) or it is an error at graph-definition time, not a race at runtime. This converts a debugging problem into a definition problem, and is the highest-value rule here.
2. **Nodes declare `reads` and `writes`; they receive a projection, not the whole state.** A node that sees all state eventually depends on all state, and then nothing is replaceable or unit-testable.
3. **Refs travel, payloads do not.** Small typed scalars, IDs, verdicts and status on the edge; drafts, diffs, logs and traces in the artifact store, content-addressed. Inline payloads make state grow without bound, replay expensive, and run-to-run diffing impossible.
4. **Agent output is a proposal, never a write.** The agent returns structured data; the harness validates against schema, checks writer ownership, and appends. An agent that can write state directly can write its own verdict.

**Loop contracts.** Every cycle requires `max_iterations`, a monotone progress measure (checks passing, error count falling), and a budget ceiling. A loop that cannot demonstrate progress exits to escalation rather than iterating.

**Sequencing note.** The contract is cheap; the engine is expensive. A linear pipeline is a DAG with one path. Phase 1 is written against this contract with a single path — adding branching later is adding *edges*, not rewriting.

## Design everything, build in stages

The blueprint covers every stage from 0 to the final one. Implementation is staged. These are not in tension: **interfaces are cheap and prevent rework; implementations are expensive and cause it.** The prior attempt did not fail from designing too much — it failed from *building* ahead of validated need.

The blueprint carries three fidelity levels, and the level is stated explicitly so nothing gets built against a contract that was a guess:

- **Frozen** (Phases 0–2) — fully specified, typed, committed. Changing these is a breaking change.
- **Provisional** (Phases 3–4) — shape and responsibility specified, signatures sketched, expected to move. Safe to design against, not safe to depend on.
- **Directional** (Phases 5–7) — the seam is named and the constraint it must satisfy is stated. No signatures. Writing signatures here before observing Phase 1–2 failures produces confidently wrong contracts, which are worse than none.

### Cross-stage invariants

These hold at every stage and are the actual source of forward-compatibility. Each costs hours in Phase 0 and costs a migration later.

| Invariant | Why it must be day-one |
|---|---|
| **Tenancy scope on every table** (`org_id`, `project_id`) even with one tenant | Retrofitting multi-tenancy means a full migration plus rewriting every query and every access check. The single most expensive omission on this list. |
| **Append-only for evidence and state transitions**; no destructive updates | Replay, provenance, and audit cannot be added later — they must be inherent. Retrofit is a rewrite. |
| **Content-addressed artifacts** (sha256 keys) | Deduplication, integrity, and run-to-run diffing all follow from it. Retrofit means re-ingesting everything. |
| **Typed, sortable IDs** (UUIDv7 or ULID; distinct types per entity) | Cheap now. Later it is a migration plus a class of ID-confusion bugs you will not find. |
| **Idempotency key on every mutating operation** | Retries are inevitable from Phase 3. Without keys, retries corrupt. |
| **Schema versions on state, criteria, and artifacts** | You will change all three. Unversioned records cannot be replayed against the code that produced them. |
| **Async-first API surface** — long operations return a job ID, never block | Converting sync endpoints to async later breaks every client. Trivial to do from the start. |
| **Structured logging with trace/span IDs from the first commit** (OpenTelemetry semantics) | Correlation cannot be reconstructed retroactively. |
| **Cost and token accounting per run** | Phase 4 autonomy gates need this history to exist *before* Phase 4. |
| **Causality recorded** — every record carries what caused it | "Why did this happen" is unanswerable if the link was never stored. |
| **Deterministic seeds and pinned versions** on every computation | Non-negotiable for a replay-based product. Reproducibility is the product. |
| **All external systems behind ports** (LLM provider, sandbox, VCS, artifact store, dataset source) | The entire premise is that agents are replaceable workers. That is only true if they sit behind an interface. |
| **Policy as configuration, not code** — protected paths, permissions, thresholds | These change constantly. Hard-coded, every change is a deploy. |

### Confidently deferred

These are expensive now and no more expensive later, because the invariants above already make room for them: Kubernetes, microservices, message bus, graph database, multi-region, autoscaling, RBAC administration UI, caching layers, distributed-tracing backend. None require changing what Phase 0 builds.

## Documentation architecture (Alfred)

Documents that describe the system drift from it. In a company where agents read documentation as context, a stale document is not merely unhelpful — it is a corrupted instruction propagating into every task. Same hazard class as an agent writing its own verdict.

Therefore documents are classified by **what stops them from lying**, not by topic:

| Kind | Source of truth | Drifts? |
|---|---|---|
| **Executable spec** — schemas, policies, agent definitions, protected paths, thresholds | YAML/Pydantic loaded by the harness | No — violation fails CI |
| **Generated** — API reference, metric catalog, port catalog | Derived from code/registry, never hand-edited | No — regenerated on build |
| **Immutable record** — ADRs, postmortems, evaluation reports, benchmark runs | Append-only, dated, never revised | No — historical claims |
| **Living prose** — charter, objectives, boundaries, guides | Human-written | **Yes** — the only category that rots |

**Rule: every document declares its enforcement mechanism. No mechanism means it must be small and human-owned.**

Corollary: most governance artifacts should not be prose. A security protocol in markdown is a wish; the same rules in `policy.yaml` loaded by `PolicyEngine` are a control. An agent definition guide is advice; an agent definition *schema* is a contract. Push everything possible into the executable category.

### Register (7 tiers, ~55 documents)

- **Tier 0 — Constitution** (prose, short, human-owned): Charter and non-goals; Operating Principles; Autonomy Boundaries; Risk Register; Glossary.
- **Tier 1 — Architecture**: System Blueprint (this file); Domain Model (generated from Pydantic); Port Catalog (generated); State & Graph Specification (executable, LangGraph schema); Data Architecture (executable, Alembic); Cross-Stage Invariants (executable, CI lint); ADR log (immutable); Technology Selection Records (immutable).
- **Tier 2 — Build protocol**: Stage Gate Definitions (executable CI gates); Build Protocol; Task Specification Standard (executable schema); Criterion Authoring Guide; Coding Standards (ruff/pyright config); Testing Strategy; Review Protocol; Definition of Done (merge gate); Branch/Release/Deploy Protocol (CI workflows).
- **Tier 3 — Agent specifications** (mostly executable): Agent Definition Standard; Agent Catalog (one spec per agent — responsibility, IO contract, tools, permissions, criteria, escalation); Tool Specification Standard (contract, side effects, blast radius, idempotency); Context Engineering Guide; Instruction/Prompt Standard (versioned, tested); Agent Evaluation Protocol; Autonomy Graduation Policy (thresholds, evidence, **revocation**); Escalation Protocol; Handoff Contract Standard.
- **Tier 4 — Security & governance**: Threat Model (prompt injection, tool poisoning, reward hacking, exfiltration, model substitution); Permission & Identity Model; Protected Paths Policy; Sandbox Specification; Secrets Management Policy; Supply Chain Policy; Data Classification & Handling; Audit & Retention Policy; Human-in-the-Loop Policy.
- **Tier 5 — Product**: Product Requirements; Domain Specification (AV risk metrics with citations and units); Metric Catalog (generated); Validation & Benchmark Protocol; API Reference (generated); Model/Algorithm Cards (assumptions, limits, validity envelope); Customer Documentation.
- **Tier 6 — Operations**: SLO/SLI Definitions; Observability Standard; Runbooks; Postmortem archive (immutable); Cost Management Policy.
- **Tier 7 — Meta**: Documentation Standard (this taxonomy, ownership, drift detection); Onboarding Guide (serves humans and agent context alike); Decision Index (generated).

Roughly 60% of the register should be executable or generated rather than prose.

### Authorship boundary

Agents may produce **generated** and **executable** documents — both have ground truth (the code, the CI gate). Agent-written prose has none and is therefore unvalidatable output of exactly the kind this architecture exists to prevent. **Tier 0 remains human-authored permanently.** This is decision 11's rule applied to documentation, not a new policy.

Documentation lives in the repository, versioned with code, changed through PRs. A wiki or documentation site held elsewhere is a drift generator by construction.

### Decision 17 — the full register is written before Phase 0 code

This was chosen with the waterfall risk explicitly on the table. The risk is real: Tier 3 and Tier 5 content written before Phase 1 describes agents and failures never observed. Writing them is not the hazard — *believing* them is. Four mitigations make the choice survivable:

1. **Status header on every document**: `frozen` | `provisional` | `directional`, matching the port fidelity levels. A pre-Phase-1 agent catalog is `directional` — a labelled hypothesis.
2. **Evidence basis declared**: `evidence: none — written pre-Phase-1` is an honest and expected value. Without the field, speculation is indistinguishable from 200 observed runs.
3. **Falsification condition required** on any document whose evidence basis is empty: *"this document is wrong if X is observed."* This converts the register from speculation into a scored set of predictions, and is what makes writing it early a net gain rather than a liability.
4. **Thin and time-boxed**: two pages with correct structure beats twenty with padding. Roughly 120–200 hours at current capacity — capped, and written in dependency order so stopping early still leaves the load-bearing documents complete.

**Document header contract** (enforced by doc lint):

```yaml
status:        frozen | provisional | directional
owner:         human | generated | executable
enforcement:   ci-gate | schema | generated | review-cadence | none
evidence:      <what this is based on, or "none — written pre-Phase-N">
falsifies_if:  <observation that would invalidate this doc>   # required when evidence is none
supersedes:    <doc id, if any>
review_after:  <phase or date>
```

**Writing order** (dependency-ordered, not tier-ordered):
1. Documentation Standard — defines the header contract every other document uses
2. Tier 0 constitution — 5 short documents
3. Schemas across Tiers 1–3 — agent definition, task specification, tool specification, criterion, state/graph, stage gates
4. Tier 4 security and governance
5. Remaining prose content
6. Generated documents last — they require the code to exist

**Decision 44 — The evidence store IS the memory; typed views + gated promotion. No extraction pipeline.** Memory = SQL/typed views over the append-only evidence store (failure taxonomy by metric class, per-capability merge history, prior artifacts by content hash). Anything worth injecting into future agent context graduates through the D32 register — human-reviewed, versioned, evidence-based, expiring — and its version joins the D19 fingerprint. In-task retrieval stays agentic (grep/read, D26-recorded). Rationale: an LLM-extraction memory layer (Mem0/Letta/Zep class) is (a) an unfingerprintable nondeterministic write path into agent context, breaking D19; (b) agent-authored config influencing successor agents — the D20 boundary, and the documented memory-poisoning propagation path; (c) an automated producer of exactly the unvalidated-prose class D32's evidence shows degrading performance −10%. Framework vendor wins are measured on conversational recall (LoCoMo class), not coding outcomes. *Pending verification when research quota resets (script saved: `alfred-memory-research`): local embedding index as read-only view over evidence; KV-prefix caching reality on the MLX lane; Cemri inter-agent failure specifics.*

**Decision 45 — Caching: three layers, two adopted, one rejected.**
- **KV-prefix cache (serving layer) — adopted, and it constrains Phase 0.** The D26 seed is layered **most-stable-first**: static conventions → protected-path list → capability context → task-specific frame. Any token change invalidates everything after it, so prefix *order* is architecture, not optimization — retrofitting it invalidates every cached prefix and every fingerprint. Zero correctness risk (KV reuse of an identical token prefix is the same computation). Attacks the binding constraint directly: prefill toll becomes near-one-time across tasks.
- **Task memoization (harness layer) — adopted.** Identical full D19 fingerprint → reuse the verdict. Deterministic; it is what the fingerprint is for.
- **Semantic caching of judge/triage outputs — rejected.** A near-miss false hit returns a wrong verdict with no run behind it; for the advisory judge that is a *silently suppressed escalation*, and D31's entire value is catching things that look similar but are not. Semantic similarity is the wrong equivalence class for verdicts.
- **Phase −1 gains a measured question:** whether mlx-lm / LM Studio persist KV across *separate requests* (llama.cpp does via `--cache-reuse` / slot save-restore). If MLX cannot, that may tip the serving-stack choice on its own.

**Decision 46 (revised) — A2A deferred to Phase 6; the handoff contract is the sole comms mechanism.** Initially adopted for future-proofing, then deferred once MAST supplied per-mode frequencies: the failure modes an inter-agent transport or shared-memory layer would address are **the two smallest of fourteen** — information withholding **1.66%**, ignored other agent's input **0.17%** — while the dominant modes are agent-internal reasoning defects no channel fixes (step repetition **17.14%**, reasoning-action mismatch **13.98%**, fail to ask for clarification **11.65%**). A protocol with no counterparty is maintenance cost, a second fingerprint field (D40) and a second injection surface, bought against 1.8% of measured failures.

**What stands instead:** typed LangGraph channels with Pydantic schemas and the Postgres checkpointer; **one owning writer per field**; refs travel, payloads live in the artifact store; agent output is a proposal. Handoffs carry **content-addressed evidence refs, never agent-authored summaries** — a summary is lossy compression by an interested party, so the successor reads what it needs (D26-recorded). A2A/ACP/MCP-as-agent-bus, blackboards, and shared mutable memory stores are all rejected for now. Re-adoption at Phase 6 costs little precisely because the handoff contract already carries everything such a protocol would serialize — that was the containment's purpose, and it survives the deferral.

### Memory/retrieval/caching research (run 4: 6 sweeps, 269 fetches, 108 claims; verify pass pending)

**DECISIVE FOR PHASE −1 — prefix caching is architecture-dependent, and it breaks on gpt-oss-120b.** mlx-lm issue #980: prefix cache reuse works only for **pure full-attention** models. `gpt-oss-120b` (sliding + full attention hybrid) gets **zero reuse — the entire cache is erased and recomputed every turn, silently, with no error**. `MiniMax M2.5` (pure full-attention MoE) works, with a reported **29 s → 3 s** reuse win. Also broken: Gemma 3, Llama 4 Scout/Maverick, Qwen 3.5 (raises TypeError). LM Studio's MLX engine v1.8.5 ships disk-backed prompt caching with the *same* hybrid exclusion. Consequence: D45's KV-prefix win — the direct attack on your binding constraint — is **unavailable on gpt-oss-120b and available on MiniMax M2.5**. Combined with MiniMax's +23pp Terminal-Bench edge, Phase −1's choice is now heavily weighted before it runs; it must measure prefix-reuse hit rate explicitly, not just prefill throughput.

**Serving-stack reality (fetched from source, not docs):**
- `mlx_lm.server` already reuses KV **across requests** via an in-memory LRU keyed on longest-common-prefix (`--prompt-cache-size`, `--prompt-cache-bytes`); `mlx_lm/models/cache.py` exposes `make/save/load/trim_prompt_cache`, `QuantizedKVCache`, `RotatingKVCache`. **Cross-process/restart persistence does NOT exist** — PR #1405 is open, unmerged. Reuse is in-process only until then.
- `llama.cpp` has the stronger story today: `--cache-prompt` (default on), `--cache-reuse N` (KV shifting), `--cache-ram` (default 8192 MiB), and `/slots/{id}?action=save|restore|erase` with `--slot-save-path` — genuine cross-request *and* cross-session persistence.
- vLLM does not run natively on Apple Silicon GPU upstream; `vllm-metal` is a plugin and its own published table shows llama.cpp faster (345.1 tok/s at max_tokens=512).

**Decision 45 amended — KV reuse is not verdict-safe.** llama.cpp's own README states prompt-cache reuse "may introduce nondeterministic results depending on batch sizes." Therefore: **KV/prefix caching sits strictly on the agent/claim side of the D5/A1 boundary and is forbidden inside any deterministic verdict node.** `CriterionRunner` runs uncached. This costs little (criterion runs are short) and preserves the property the whole architecture rests on.

**Decision 37 turns out to be a correctness safeguard, not just a constraint.** mlx-lm issue #965: at 16+ concurrent requests `mlx_lm.server` leaked KV cache **between prompts** — one prompt's content appearing in another's response, dropping an agent score 0.727 → 0.456. Alfred's single serialized lane avoids this by construction.

**Prefix-cache invalidation is binary and hash-chained** (vLLM's published spec; MLX/LM Studio implement the same idea): block hash = f(parent hash, exact tokens). One changed token upstream invalidates every downstream block. **Architectural corollary now locked into D26:** any retrieved or per-task-variable content must be appended **after** the immutable seed. Placing retrieved memory early destroys caching for conventions and task frame on every task — which is precisely where a naive memory-injection design would put it.

**Memory frameworks — D44 confirmed, with harder reasons than I had:**
- Every credible framework (Mem0, Zep/Graphiti, Letta, Cognee, LangMem) is **LLM-extraction-based**. On one serialized lane, memory writes **contend with task inference for the only compute resource** — "free background memory" is architecturally false here.
- **Graphiti hard-requires a graph database** (Neo4j/FalkorDB/Neptune/Kuzu); no relational backend. Adopting it breaks "Postgres is the single source of truth."
- The headline benchmark is unusable for selection: **LoCoMo scores the same system (Zep) at 84%, 75.14%, 65.99% and 58.44% depending on who ran it**, in an unresolved vendor dispute.
- An independent academic evaluation ("Anatomy of Agentic Memory", UT Dallas / UC Davis / Texas A&M) places LoCoMo (~20k tokens) and MemBench (~100k) in a **saturation regime** where full-context baselines suffice — and measures MemoryOS at **32+ s latency vs ~1.7 s for full context**.
- Same evaluation: **open-weight backbones produce significantly higher format-error rates during memory operations, causing "Silent Failure"** — a direct D35 risk, since any extraction pipeline would run on the local model.

**Semantic caching rejection confirmed with a concrete failure.** A documented case (arXiv 2605.20630): a query for one sensor, scope and time window returned a cached answer produced for a *different* sensor, scope and window — wrong on three dimensions — and the reranker scored that wrong match **0.97**, above a strict 0.92 threshold. Measured system F1: 0.64. Separately (arXiv 2602.18922): **"check email" vs "send email" embed at 0.91 cosine while true paraphrases of one intent score 0.65** — action-distinguishing pairs are *closer* than synonymous ones. GPTCache's own paper concedes no threshold eliminates false hits; it only trades them against false misses.

**Open challenge to D44 (needs the verify pass and a Phase 2 measurement):** in the one local-hardware head-to-head found (42 experiments, Mac Mini M4 Pro 64 GB, MLX), agentic search beat RAG **only when a frontier model drove the search** (4.7/5 vs 3.2/5). A **fully-local** model driving agentic search scored 3.2/5 — *tying* RAG. Under D35 this weakens "agentic retrieval beats an index," which was an assumption behind D44's no-index stance.

**Decision 47 — Read-only retrieval index, settled by measurement in Phase 2.** D44's invariants all hold: no extraction pipeline, no memory framework, no new authority over agent context. Added: an embedding + full-text index over the repo and evidence store, built **Postgres-native** (pgvector / tsvector, hybrid RRF) so single-source-of-truth survives, and strictly **derived and read-only** — the index is a materialized view of content that already exists, never a place anything is authored. Injected results are appended **after** the immutable seed (D45's hash-chain rule), so prefix caching survives. Phase 2 runs "agentic search alone" vs "index-assisted" as a measured comparison on the golden set; whichever wins becomes `context_strategy_version` and enters the D19 fingerprint. Rationale: the assumption behind a no-index stance — that agentic grep/read beats an index — is supported for *frontier-driven* search (4.7/5 vs 3.2/5) but **not** under pure-local, where a local model driving agentic search merely tied RAG at 3.2/5. Under D35 that assumption is unsupported, so it gets measured on Alfred's own task class rather than inherited from a study with a different task shape. Local embedding model selection (footprint alongside a ~110 GB model) is a Phase −1 sizing question.

### Verify pass (run 4 complete: 13 agents, 138 further fetches) — corrections and two fatals

**CORRECTION, and it reverses an earlier entry in this file.** The claim that prefix caching is broken on `gpt-oss-120b` is **stale and wrong**. mlx-lm issue #980 (11 Mar 2026) was fixed by **PR #999 (14 Mar 2026)** — the ring buffer is linearized during trim and physical buffer size separated from logical RoPE position — and **validated on `gpt-oss-120b` at 98% cache hit / 3.37× speedup**. Two further reading errors in the earlier entry: the #980 numbers were never a controlled comparison (gpt-oss ~1.5 s cold vs MiniMax ~29 s cold — a ~20× prompt-scale difference, so "zero improvement" was near the HTTP noise floor); and LM Studio v1.8.5 caching **local attention layers** means it is built *for* sliding-window architectures, not excluding them. **Prefix caching is not a valid ground for model choice.** MiniMax M2.5's +23pp Terminal-Bench edge stands unaided. Process lesson worth keeping: one community bug report with non-comparable timings was nearly used to pick a base model.

**FATAL — A8 is not enforced by anything currently named.** LangGraph `private` state schemas "do not hide channels from stream"; `output_keys` is a caller-side argument, not a graph-level guarantee; the Postgres checkpointer persists everything; and a filter predicate on an ANN index is not a boundary. **Fix: held-out values live in a separate table behind a separate DB role**, materialized by `CriterionRunner` at verdict time only — enforced by SQL grant, never by channel visibility. If subagent isolation is ever part of the story, explicitly deny `SendMessage` and forbid context forks: a sibling roster is a lateral channel.

**FATAL — D20 + memory, confirmed with attack data.** Any memory store agents write and later read into context is, by Alfred's own definition, agents editing agent-influencing config — and the write channel needs **no privileges** to be captured. MINJA: **98.2% injection / 76.8% attack success** by a query-only actor. AgentPoison: **>80% ASR at <0.1% poison rate**. Memory-mediated injection is demonstrated to survive session boundaries and reach orchestrators. D44's no-extraction stance is now evidentially load-bearing, not merely tidy.

**MAJOR — D16 rests on convention unless mechanically enforced.** LangGraph only errors on *concurrent* unreducered writes; a sequential write to a verdict field raises nothing. Fix: schema partitioning **plus a CI lint that no agent-invoking node's return annotation includes a verdict field**.

**MAJOR — D26 conflict inherited from OpenHands.** It ships `CondensationSummaryEvent`, a built-in compaction path inside the agent's own memory stream, which Alfred would inherit silently. Must be asserted off at startup — "no compaction upstream of a verdict node" is otherwise violated by the executor rather than by Alfred's code.

**MAJOR — a terminal verdict node is necessary but insufficient.** MAST, verbatim: *"Sole reliance on final-stage, low-level checks is inadequate. Robust MAS, like complex software systems generally, require modular unit testings."* Verification failure modes are not rare (premature termination 7.82%). This reinforces major-fix #1 (seeded-defect suite) and argues for per-node checks, not just the gate.

**Decision 45 finalized — three tiers, split on the D5/A1 boundary:**
- **Tier 1 — exact-fingerprint memoization, everywhere including verdict-adjacent paths.** Zero false-positive mode (exact hash, not similarity). Key on the full D19/D40 fingerprint; store `{fingerprint → result_ref, verdict, produced_at}`; record a memoization-hit event in the hash chain so replay stays faithful. **This is the only cache that removes inference rather than accelerating it.**
- **Tier 2 — KV prefix caching, agent/proposal side ONLY.** llama.cpp's README: reuse can produce nondeterministic results because "logits are not guaranteed to be bit-for-bit identical for different batch sizes" — a backend numerics property that **cannot be configured away while reuse is on**. Forbidden in any verdict node. Operational requirements: the **MLX lane must be a long-lived daemon** (no cross-process persistence — PR #1405 unmerged; a supervisor restarting between tasks silently zeroes 100% of the benefit); raise `--prompt-cache-size` well above its default of **10**; set `cache_salt` (or equivalent) to `context_strategy_version` so a strategy change structurally cannot reuse stale cache; treat hit rate as an observable.
- **Tier 3 — semantic caching: build none, anywhere.** Honest caveat recorded: the cited evidence is intent classification over short utterances, not judge outputs over long structured contexts — nobody has measured Alfred's actual case. The rejection stands on the intrinsic threshold trade, not on transfer.

**Decision 47 amended — ship v1 with no index beyond Postgres.** Parameterised SQL over the evidence store; **tsvector FTS** for text and code; agentic glob/grep/read inside the sandbox; file-granular retrieval, no chunker. Record every retrieval call and returned row IDs as a D26 read. Hash the retrieval-function source, FTS configuration and seed into `context_strategy_version`. Then **instrument**: grep-loop token cost, lane wall-clock, and retrieval miss rate (task failed *and* the needed file was never read). Revisit embeddings when miss rate measurably costs verdicts or the repo passes **~1000 files**, settled by a deterministic A/B in Alfred's own harness. Reason for demoting embeddings from v1: Alfred's dominant query shapes are **exact tokens** — fingerprints, decision IDs, metric names, hash-chain entries — precisely where embeddings fail, and BM25 with word-level splitting is the measured winner for code-to-code retrieval. Stated honestly: the anti-embedding case is weaker than usually presented (Cursor measures **+12.5%** from semantic search alongside grep), so this is a sequencing call, not a verdict. **pgvector cliff if ever adopted:** 2110 QPS at 2M vectors → **12.9 QPS at 5M**, recall 0.99995 → **0.5444**, once index size exceeds `shared_buffers` — and it never reclaims space on delete, which interacts badly with D43's append-only monotonic growth. Second leg behind BM25 only, with a hard size budget and scheduled rebuild.

**Memory frameworks — D44 confirmed with sharper reasons.** Mem0 is **ADD-only, no delete path**, so it structurally cannot implement D32 expiry. Graphiti has no relational backend (Neo4j/FalkorDB/Neptune/Kuzu only) *and* hard-requires structured output from providers that "reliably honor it (OpenAI, Anthropic, Gemini)" — the D35-compliant fallback is forbidden and the failure is **silent** (a dropped entity yields a thinner graph, no error). Letta's **own** benchmark found a plain filesystem beat framework memory (74.0% vs 68.5% on LoCoMo), attributing it to models being effective with tools in their training data. LLM-extraction format-error rates: **17.91% for gpt-4o-mini, 30.38% for a small open model** — directly disqualifying under D35. One correction to my own earlier framing: "every framework breaks Postgres-SSOT" is **false** — Cognee documents running fully on Postgres+pgvector; it is disqualified on the LLM-extraction write path and licensing instead.

### Sequential tool-calling probe — 2026-08-12, and the serving layer was the whole story

**The gap it closes.** D41 selected the lane on prefill throughput, one prefix-reuse pair, ten *single-shot* tool calls and five *single-shot* code generations. A grep across the plan and all 57 documents returned zero hits for `multi-turn`, `long-horizon` and `goal-seek`; `toy_tasks.py` contains the string "tool" zero times. The lane was chosen with no agentic signal at all, and agentic work is dominated by exactly what was not measured. `bench/probe_agentic.py` closes the first two axes.

**Design, each constraint answering a way the probe could lie.** Scenario data is generated from a per-run seed, so no answer exists in training data and a guess cannot land. Ground truth is computed by the harness from the same seeded data, never from the model's report. Tools fail deliberately — one transient error, one out-of-range error with an informative message — because recovery cannot be measured if no error occurs. Fabrication is scored separately from wrongness by counting successful *data reads*: an answer submitted with fewer reads than could have produced it is a confident unsourced number, which is the failure this architecture exists to catch. Five tasks, depth 1–4 required reads, plus list and describe hops.

**Result — 4 seeds × 5 tasks, 20/20:** chain completion 1.0, correct 1.0, fabrication 0.0, error recovery 1.0, mean 4.1 turns and 4.75 tool calls per task. The model also **parallelizes independent calls** (four `describe_scenario` calls emitted in one message) and recovers from both error classes — retrying a transient failure on the same arguments, and correcting `step=8` to `step=7` after an out-of-range message. The one "repeated call" per run is t2's *correct* retry of the injected transient error; the metric counts it as repetition and that reading should not be inverted into a defect.

**The finding that matters is not the model.** On the first run the probe reported **chain completion 0.2** and would have argued for abandoning the lane. It was wrong. The model was chaining perfectly and emitting its *final* tool call into the **content channel** as prose — valid JSON, wrong channel — in two distinct syntaxes: `submit_answer\n{"value": 13.0994}` and `submit_answer(10)`. Across four seeds, **3–5 calls per run, roughly 15–20% of all tool calls**, arrive this way, disproportionately the terminal one. This is precisely the D40 class the plan predicts — "a schema-capable model still emits invalid JSON through a bad serving layer" — except the JSON is fine and the *channel* is the defect, which is worse because nothing errors: the agent simply appears to stall.

**Hard Phase 1 requirement, now in Failure Semantics:** the harness parses tool calls from the content channel and counts them as a serving-quality metric, with recovery restricted to unambiguous cases (a named tool with a parseable object, or a single-parameter tool called positionally) because anything wider is a harness guessing at agent intent. Identical model behaviour reads as **20% or 100%** chain completion depending solely on whether this exists.

**Still unmeasured: long-horizon execution (item 3) and goal seeking (item 4).** Deepest chain here is 9 tool calls over 5 turns; Phase 1 assumes ~30 turns. Deliberately not synthesised — Phase 1 is that measurement, provided the instrumentation to emit turns-per-task, tool-failure-recovery rate and escalation-cause distribution exists before it starts. Item 5, weighing consequences, is handled by *not* delegating it: D22 assigns the human whether the criterion was the right criterion and what the future coupling cost is, and Autonomy Boundaries names it permanently outside.

**Process note, the fourth in this project.** The probe's first result was a harness artifact that flattered a conclusion — here a catastrophic one rather than a favourable one, but the same failure of measuring before verifying the instrument. Caught by dumping the actual conversation rather than trusting the aggregate. The unsalted prefill, the 1.3× object benchmark, the 0/10 tool-calling after a silent lane reload, and now this: **four for four, every headline number in this project has been wrong on first read.**

### The prefix-reuse anomaly is RESOLVED — it was `--parallel`, and my own command caused it (2026-08-13)

**Cross-request KV reuse is controlled by the lane's parallel slot count, not by context length.** At `--parallel 1` it works; at any value above 1 it is off completely. Independently reproduced by me, both cells, on a 36,018-token prefix at full 262,144 context:

| lane | cold | warm | speedup |
|---|---|---|---|
| `--parallel 1` | 35.03 s | 0.249 s | **140.7×** |
| default (`--parallel 4`) | 34.99 s | 34.68 s | **1.0×** |

The agent's 2×2 is what settles it: the falsifying cell was **28,672 + parallel 4**, because the original 79.4× was measured at 28,672, so "reuse degrades with context" required that cell to show reuse. It showed none, and the mirror cell (262,144 + parallel 1) gave 84×. The small-entry-cache hypothesis was separately ruled out — four distinct ~15.5k prefixes primed, all four returned warm.

The "1.0× at 262k" was never a context effect; it was a load command missing one flag. Every occurrence of that command needs `--parallel 1`.

**Three consequences that outlive the incident:**

1. **D45 tier 2 survives at full context** — 140× at 262k — but **concurrency and cross-request reuse are mutually exclusive on this stack.** A lane cannot have both.
2. **D37 (single serialized lane) gains a second, independent justification.** It was adopted for memory arithmetic and later found to also prevent a KV-leak-between-prompts bug; it now turns out to be *required* for prefix reuse as well. Three unrelated arguments converge on the same constraint.
3. **Slot count is not in the fingerprint, and must be.** A lane at 140× and a lane at 1.0× are indistinguishable on record under D19/D40 today. That is a fingerprint field the server sets by default and nothing observes — the same class as `loaded_context_length`, which this project already had to add for exactly this reason. **The real threat is an open standard that already specifies the record.** Modelica/prostep ivip **SSP Layered Standard Traceability 1.0.0** (`https://ssp-standard.org/ssp-ls-traceability/1.0.0/`) — **verified first-hand, 253,204 bytes retrieved 2026-08-15**. §8.1 `SimulationResourceMetaData` carries `checksum` and `checksumType`, the latter reading *"Must be SHA3-256 for now … as specified in FIPS 202"*; `generatingTool`, `generationDateAndTime` and a `DerivationChain` section (`#sec-derivationchain`) all exist. **Two things save the position, and both are read from the spec's explicit `Use` column rather than inferred:** every one of `checksum`, `generatingTool` and `generationDateAndTime` is marked **Optional** against `version`/`name` marked **Mandatory** — so the spec draws the binary and puts provenance on the soft side of it — and **neither the spec nor its workflow guide defines re-derivation**, while what it offers in place of a recall path is a *status*, not a mechanism: `LifeCycleInformationType` (Table 13) carries a `Retracted` state — *"has been withdrawn and is considered invalid or may need to be revised"* — with a mandatory `date` and a mandatory `Responsible`, and an optional `Signature`. That is a withdrawal marker on a **file**, with no impact analysis, no enumeration of the downstream results affected, and no advisory naming versions and date ranges. Stated flatly as "no recall path" it is refutable by anyone who has read §5.5, so it must be stated as what it is: **the retraction status is specified; the recall is not.** The record is specified; the recompute and the recall are not.

Two further facts sharpen the position, both read from the spec on 2026-08-16 and both cutting against adopting the format. **`generatingTool` is defined as *"the name of the tool that generated this file"* — a name, with no version and no configuration anywhere in the record** (`fileversion` versions the file's content, not the tool), so on the exact duty D48 rests on — 2022/1426 Annex III Part 4 storage of every toolchain version used — the record is **not** specified. And **the record's own format version reads *"0.x for this pre-release"*** in Table 62, inside a document published as Layered Standard 1.0.0.

**Restatement, replacing the withdrawn clause:** not *"reproducibility is unclaimed"* but **"specified but not shipped at the metric level, and not re-derivable or recallable by anyone."** A funded consortium already describes itself as *"developing solutions for ensuring the traceability and reproducibility of simulation tasks"* (prostep ivip, *Guard Rails for Simulation Credibility Standards*, §2.1). The idea is claimed. The implementation is not.

The durable-execution build/buy decision (Temporal vs. LangGraph checkpointer vs. Postgres queue) is made **here**, against measured need — deferred because Phase 1–2 tasks are single-shot and idempotent, so checkpointing buys nothing.

**Review backpressure (D42-adjacent, from red team):** dispatch halts when open-PR or pending-escalation count exceeds a configured ceiling; explicit drain mode for operator absence; review-backlog depth is a first-class metric alongside wall-clock-per-merged-task.

- **Exit:** a stated wall-clock-per-merged-task target sustained; zero lost work; killed process loses no completed work; backpressure demonstrated (queue drains when review stalls).
- **Forbidden:** adopting a workflow engine before a work item genuinely spans multiple irreversible steps.

### Phase 4 — Earned autonomy *(incorporates A3/A4/A5: mutation strength has no gating role)*

Auto-merge per task-class only where **measured per-task merge rate, held-out composed property pass rate (A3/A5), and measured defect-escape rate** clear explicit thresholds. Graduation path for agent-authored criteria using Phase 1–2 paired data, calibrated on held-out pass rate only (D33). mutmut appears nowhere in this gate — it survives only as regression on the trusted human-built skeleton (A4).

- **Exit:** at least one task-class runs unattended with a measured defect-escape rate.
- **Forbidden:** granting autonomy by category ("tests are safe") rather than by measurement.

### Phase 5 — Planning and decomposition

An agent converts product intent into checkable criteria and dependency-ordered work. Late deliberately: you cannot specify what a good criterion looks like until you have authored a hundred real ones.

### Phase 6 — Specialization and multi-agent

Only where a measured bottleneck justifies it. Centralized durable state; no free-form agent conversation as coordination.

### Phase 7 — Streaming and operations autonomy

Real-time delivery path, validated against the batch replay harness. Then monitoring-driven diagnosis, remediation, rollback.

### Deferred indefinitely

Kubernetes, microservices — until scale pain is measured and real.

**Two documents added 2026-08-12 — the register had no home for edge cases or error handling, and both are Phase-0-falsifiable. Register now 57 documents, 21 written.**

**Failure Semantics and Error Handling** (Tier 1, executable/ci-gate) rests on one distinction: *a check that failed and a check that did not run are different outcomes*, which almost every test runner and CI system collapses. Verdicts become three-valued — `pass` / `fail` / `indeterminate` — and **`indeterminate` is excluded from merge rate on both sides**, because harness flakiness folded into either the numerator or the denominator corrupts the only number the autonomy gates read. Carries the fail-closed table (13 conditions, exactly one deliberate fail-open: backup unreachability, named and escalating), a five-class error taxonomy in which **policy violations are never retried** — a retry is indistinguishable from searching for a formulation the check does not catch — timeouts set from measured distributions rather than defaults (a 30–60 s default would abort healthy work, since prefill alone costs ~45 s at 28k), the rule that **a request timeout must not become a lane restart** (it silently discards the 32–128× prefix-cache saving), evidence-write-as-commit-point with a single serialized chain writer, recompute-never-resume on crash, and error text treated as an attack surface: sanitized into agent context, recorded raw in evidence.

**Edge Case and Degeneracy Specification** (Tier 5, human/ci-gate) is the domain half — 30 numbered cases across geometry/kinematics, trajectory sampling, and numerics, plus aggregation and invariance obligations. Its totality rule forbids **NaN as an output anywhere**, a finite number where the quantity is undefined, and exceptions as the normal representation of degeneracy (degeneracy is ordinary; exceptions also do not survive vectorized evaluation). `+inf`, `0.0` and `Undefined(reason)` are three distinct claims, and the sentinel-weakness point connects directly to the CriMe assertion audit: a test asserting `0.0` or `inf` is satisfied by a stub returning the constant, which is exactly why those measures were excluded from the verified task class. Aggregates must report `(value, n_defined, n_undefined)`. The closing argument is the important one: **degenerate cases are the highest-value held-out material in the product**, because an implementation special-cased to the degenerate inputs it was shown, and wrong on the geometrically identical case it was not, passes every visible check — the SpecBench divergence arriving with no exploit and no dishonesty anywhere in the loop.

**ADR-0001 opened the ADR log 2026-08-12 — `Undefined` representation, decided by measurement.** The edge-case spec said what must be represented and not how, and the choice propagates into every metric signature, the API schema, criterion comparison and the result hash, so it is a first-hour Phase 0 decision. Two measurements settled it. **(1) Pydantic v2 serializes `+inf` to `null` by default** — so under a `value: float | None` representation, where `None` means undefined, the serializer silently converts a *defined* value asserting no collision into the undefined encoding, collapsing E1 into E7 with no error anywhere; and the escape hatch emits `Infinity`, which is not valid JSON under RFC 8259 and which a strict customer-side parser rejects, in a product selling re-derivability. **Infinity therefore cannot cross a JSON boundary as a float at all**, which removes the simple option's only advantage. **(2) Per-timestep objects cost ~60× against vectorized evaluation** (0.5 ms vs 29.5 ms over 200k values), so a scalar-first type is wrong for metrics evaluated per timestep across a scenario.

Decision: two representations, one conversion point at the metric's return — `MetricSeries` (`values: float64[]` + `reasons: uint8[]`, the reason array serving as the mask so per-timestep reasons survive where a boolean mask would collapse E7/E8/E16) inside computation, and `MetricValue`, a tagged `defined`/`infinite`/`undefined` union, on every boundary. Rejected: NaN (already banned), `float | None` (measured serializer collapse), a `defined: bool` struct (invisible to `pyright --strict`, carries a plausible number in an ignorable field), and `np.ma.MaskedArray` (a mask carries no reason). Composition never absorbs — undefined inputs yield `Undefined(UPSTREAM_UNDEFINED)` with the cause chain intact.

**ADR-0002 settles the reason-code width at `uint8`, and amends ADR-0001's encoding clause.** Memory was not a deciding input (30 MB of codes against 240 MB of values on a 500-scenario sweep). Population is not either: the enum is global, so codes enumerate *kinds of degeneracy* rather than metrics × kinds — the 30-row catalog yields **7** codes today, since most rows resolve to defined values or raise as contract violations. The one design that would exhaust `uint8` is namespaced integer ranges, rejected because the per-metric declared subset constrains emission explicitly without consuming encoding space.

The substantive correction: ADR-0001 stated that reason integers enter the wire format and the content-addressed hash, which is wrong and contradicts its own wire example. **The name is what crosses the boundary and what gets hashed; the integer is a private in-memory encoding.** That makes widening to `uint16` a pure code change — no wire change, no hash change, no re-derivation of stored results — so the width is a *reversible* decision, which is why it can be settled at the cheaper option rather than hedged at the more expensive one. `0` = defined permanently; `255` = `UNKNOWN_CODE`, and an unrecognized code decodes to 255 and **never to 0**, because decoding an unknown reason as "defined" would reintroduce plausible-wrong output through the deserializer. CI fails the build at **200** allocated codes rather than 254 — a ceiling found at exhaustion is an emergency, one found at 80% is a scheduled decision — which also covers numpy's silent `uint8` wrap (`254 + 3 == 1`, no error) colliding a naive allocator with a live code. Recorded as a separate ADR rather than by editing ADR-0001, same session and nothing depending on it, because "it is a small fix" is how immutability dies.

**ADR-0003 specifies the canonical serialization (ACS-1)**, which ADR-0002 made load-bearing by putting the reason *name* rather than an integer into the hash. Measured divergences between Python's `json` and ES6/JCS, each silently changing the hash of an identical value: `1.0`/`1`, `-0.0`/`0`, `1e+16`/`10000000000000000`, `1e-07`/`1e-7`. Plus two standard-library hazards — `json.loads` accepts duplicate keys last-wins with no error, and `json.dumps` emits bare `NaN`.

The shape came from splitting one problem into two. **Artifacts are hashed as stored bytes**, so no canonicalization question arises for the majority of the volume. Only **evidence rows and result stamps** need a canonical form, and their requirement is specifically that an *external auditor* can recompute the chain without running Alfred's code — the use case that justifies chaining at all. Then the collapse: canonicalization here is almost entirely a number-formatting problem, and **encoding floats as strings deletes it** (`float(repr(f)) == f` held for all 200,000 random doubles tested, zero failures). RFC 8785 was rejected with reservations — it is a real standard with multi-language implementations, but its two hardest requirements are the two this design does not need: ES6 number formatting, the source of all four divergences, and UTF-16 key ordering, which is surrogate-dependent and measurably disagrees with byte ordering on astral characters. Canonical CBOR was rejected because an audit record a human cannot inspect with `cat` trades the wrong thing.

ACS-1: UTF-8, keys sorted by UTF-8 bytes, no whitespace, strings NFC-normalized and emitted raw, floats as shortest-round-trip strings with `-0.0` normalized, integers as int64-bounded JSON numbers, NaN and infinity never numbers, duplicate keys rejected on parse via `object_pairs_hook`, and the hash taken over `acs_version || 0x00 || record_type || 0x00 || bytes` for domain separation. The honest cost is that ACS-1 is not a standard, so a third party implements from spec rather than importing a library — given up deliberately, since these rules are ~20 lines in any language and a correct ES6 number formatter is not. **The mitigation is the deliverable: a published test-vector suite**, which for rules this simple is a complete specification and is what makes a non-standard defensible to an auditor.

**ACS-1 implemented and the vector suite published 2026-08-12 — `harness/acs/`, 63 vectors, 79 tests passing.** `acs1.py` (encoder, strict parser, `is_canonical`, domain-separated hash, zero third-party imports — the encoder guarding the audit chain must not depend on the supply chain the chain records), `gen_vectors.py`, `vectors.json`, `test_acs1.py`. Vectors describe inputs in a neutral tagged form — floats as IEEE-754 bit patterns in hex, integers as decimal strings, strings as UTF-8 hex — because a file describing a float as `2.4` would be asking the reader's JSON parser the very question ACS-1 exists to answer. Regeneration is byte-identical. Coverage includes the four divergence cases, subnormals and both double extremes, NFC/NFD equality, astral-plane key ordering (the case where RFC 8785's UTF-16 rule disagrees), control-character escaping, `true` versus `1`, the ADR-0001 tagged `MetricValue` arms, domain separation, and six encode-error plus four parse-rejection codes.

**ADR-0004 — the vectors caught a real underspecification in ADR-0003 within the hour.** "Shortest round-tripping decimal" is not a specification: correct implementations agree on the **digits** and disagree on the **presentation** (`1.0`/`1`, `100.0`/`100`, `1e+16`/`10000000000000000`, `1e-07`/`1e-7`), so a JavaScript implementer using `String(x)` would have reintroduced two of the four divergences ADR-0003 cites as its own motivation — inside a rule that reads as though it had settled them. Fixed by pinning normalized scientific: `sign? digit "." digit+ "e" "-"? exponent`, one digit before the point, no `+`, no leading zeros. `1.0e0`, `1.0e2`, `2.4e0`, `3.0000000000000004e-1`, `5.0e-324`. Verified bit-exact on 50,000 random doubles with the grammar shape asserted on 20,000 more. This is the argument for the vectors being the specification rather than the prose, and it makes the published suite non-negotiable rather than a nicety.

**Cross-language verification done 2026-08-12 — an independent JavaScript implementation reproduces every canonical byte string and every digest: `harness/acs/acs1.mjs`, 136 checks, 0 failures.** This converts the central claim from an assertion into a result: a third party can recompute Alfred's evidence-chain digests without running Alfred's code. The JS side implements a hand-written parser rather than using `JSON.parse`, for the same reason Python needs `object_pairs_hook` — the built-in keeps the last of a duplicate key pair silently, so tampering is invisible to a reviver. `toExponential()` with no argument yields the same shortest-digit sequence as Python's `repr`, so ADR-0004's grammar needs only presentation rules on top of it, which is what makes it portable.

Three host-language findings, recorded for future implementers: **`Number` cannot represent int64** (`Number("9223372036854775807")` is `9223372036854776000`, so ACS-1 integers must be `BigInt`); **`TextEncoder` silently substitutes U+FFFD for a lone surrogate** where Python raises, making the corruption invisible without an explicit check; and **JavaScript cannot distinguish `1` from `1.0`**, so the int/float split must be carried by wrapper types on the way in — the canonical form itself is unaffected, since floats are strings there.

**The second implementation found a defect in the first.** Python's `parse_strict` accepted `{"a":1.5}` and an out-of-range integer — neither can occur in canonical form — because `json.loads` was left on its defaults; fixed with `parse_float`/`parse_int` hooks. That divergence was invisible from inside either implementation, and it is the whole return on writing a second one. Spec point settled at the same time: **parse cases are normative in *whether* they reject, not in the code they reject with**, since a host rejecting a construct in its own tokenizer reports its own error; encode-error codes stay normative as ACS-1's own semantics.

**The suite is mutation-checked, because 136/136 on a first run is also what a vacuous verifier reports.** Injected defects in the JS encoder — `+` on the exponent, NFC dropped, UTF-16 key ordering, duplicate detection removed, surrogate check removed — fail 32, 9, 12, 3 and 1 checks. Suite widened from 63 to 76 vectors after the first control run showed margins of 3, 4 and 1. The remaining thin margins (duplicate detection, surrogate check) are recorded as a known weakness rather than presented as coverage.

Worth recording as process: the 60× benchmark first reported **1.3×**, because it compared object construction against array allocation-plus-sum and did no arithmetic on the object path. The favourable number was measuring the wrong thing — the same failure as the unsalted prompt that turned a prefill measurement into a cache-hit measurement in Phase −1. Two for two on benchmarks that flattered the option already being leaned toward.

Longest document is 175 lines; all sit well under the 500-line limit. Generated documents (Domain Model, Port Catalog, Metric Catalog, API Reference, Decision Index) remain stubs by design — they require the code to exist.

## Priority correction — the factory's own operator interface was never specified (2026-08-15)

**Effort had drifted onto the product wedge while the factory's human interface sat unowned.** The AV domain is substitutable; the factory is not. Days of D30/D48/demand-gate work ran while a structural gap in the factory itself went unnoticed.

**The gap, verified by grep across all 58 register documents:** exactly one mentions a UI, tangentially. `human-in-the-loop-policy.md` is a stub carrying `review_after: Phase 3`. `review-protocol.md` specifies the review *protocol* and no surface.

**That Phase 3 deferral is a sequencing error, not a cosmetic one.** Phase 1 puts a human gate on every one of 20+ tasks, and major-fix #10 makes *"projected human-minutes ≤ capacity"* an executable stage gate whose input is **human minutes per task** — a number Phase 1 is supposed to produce and cannot produce trustworthily if every review is a terminal window and a patch file. **The gate depends on a measurement the plan gave no instrument for.**

**OpenHands: right executor, wrong interface.** It stays as the sandboxed executor — the Docker sandbox and the durable event stream are why it was selected and nothing changes that. But **its own frontend must not be exposed.** It ships a chat-style UI with an approval affordance; an operator approving there writes the approval into OpenHands' event stream, **inside the untrusted execution plane**, creating a second authorization path Alfred's evidence store and hash chain never see. The threat model already names the operator as T10, and an approval surface that does not write to the chain makes the most privileged actor the least audited one. There is also a framing defect beneath the plumbing: OpenHands' UI is **agent-conversation-centric** while Alfred's control plane is task/criterion/verdict/evidence-centric — approving inside a conversation means judging the agent's own account of its work, which is exactly what D22's criterion-first ordering exists to prevent.

**Boundary split for mission control:** the **command surface** (approve, decline, waive, and later grant/revoke autonomy and drain) is **inspector**, permanently agent-protected under D20. The **read model** (views, rendering, queries) is **factory** and agents may build it. Every operator action through the command surface is itself an **evidence row in the hash chain**.

**Graph and loop UI: viewer early, editor late.** An editor is premature — Phase 1 is deliberately a single linear path and a visual editor for one path is nothing. A viewer earns its place immediately, showing a run's traversal, which node wrote which field, where a loop iterated against what monotone progress measure, and where escalation fired — that is how the failure taxonomy gets read, and the taxonomy is half of Phase 1's exit. Specified as **generated** from the graph definition plus the evidence store, never hand-drawn, so it lands in the register's generated category where drift is impossible.

**Corrected order:** (1) operator interface specification — blocks Phase 1's human gate and the capacity-ledger measurement; (2) **D50** oracle assertion — blocks Phase 1's *validity*, since without it merge rate measures delegation; (3) `Worker` port contract and the OpenHands containment assertions — blocks Phase 1's build; (4) graph/loop viewer, generated, shipping with the instrumentation; (5) stamp schema version, upstream toolchain field, and the SSP-LS-Traceability format decision — Phase 0 code, unretrofittable, but downstream of the above; (6) **product wedge parked** until a Phase 0.75 conversation actually happens — no further research runs, and the two gated vendors (dSPACE SIMPHERA Result Containers, Siemens Teamcenter Simulation) become conversation questions rather than research questions.

**The capacity ledger is still unfalsifiable, and the design pass bounded it rather than guessing.** The gate is `5·n·m + F ≤ C`. Of its four terms exactly one is stated anywhere — `C` = 20+ hrs/week = 1200 min/week. `m` (per-task human minutes) is what Phase 1 exists to measure. **`n` (target tasks/day) and `F` (fixed weekly obligations) have never been written down**, which puts the gate in the state D42's kill criterion was in before it got a date.

Bounding it with stated assumptions (`F` = 300 min/week, authorship ≈ 25 min/task, escalation amortized ≈ 8 min/task) produces a finding worth more than the surface it was computed for: **at 20 hrs/week the ledger caps out near 2–3 tasks/day, and the binding term is criterion authorship, not review.** Making review instant does not lift the ceiling; Phase 2's parameterized criterion families are the throughput lever. Review's design target is nevertheless real at ≤ ~25–30 attended minutes per task — a criterion-first review fits, while a 45–60 minute full-diff read consumes the whole budget at two tasks/day and makes three impossible. **Opening the diff by default costs roughly a factor of two on the achievable task rate, and it does so invisibly**, which is the quantitative form of D22's argument. Note also that **criterion-authorship time is instrumented nowhere**, so the term the arithmetic identifies as binding is the one term Phase 1 will not measure unless that changes. **Amended 2026-08-17:** `F` = 300 is not a conservative figure but the ledger's most optimistic one — D20 forbids agents from building the inspector, so every hour of `CriterionRunner`, `EvidenceStore`, containment-assertion and command-surface construction lands in `F` for the whole of Phase 1. And `n` is undefined as *dispatched* or *merged*, a factor of two at K3's threshold. Both are operator inputs; until they exist the gate cannot be failed.

**Operator decisions on the interface, made 2026-08-15:** scope is **gate + escalation queue only** — task queue, escalation inbox with the structured attempt bundle, criterion-first evidence-bundle view, approve/decline/waive, and automatic per-review timing. No charts, no live in-flight observability, no policy editing, no agent chat. Stack is **FastAPI + server-rendered HTML** — same toolchain as the product per D13, no build step, and no JavaScript dependency closure to hash-lock under the supply-chain policy.
