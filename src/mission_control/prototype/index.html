What the factory is doing right now. This screen is deliberately drawn to look provisional — dashed edges, lighter ground, a live marker — because it renders runtime state, which owns nothing and is never evidence. The factory graph

runtime · display only
recorded handoff — artifact + hash runtime traffic — display only static default re-entry (all five rows of the table) override — upstream-only, reason recorded active idle — bound, no attempt in flight unbound — no agent binds this capability

Solid edges are handoffs the evidence chain recorded — an artifact and its hash. Dashed edges are runtime traffic, which no gate, verdict or audit may cite. There are no agent-to-agent message edges, because a handoff carries a hash and there is no field a message could travel in.

All five rows of the static-default re-entry table (docs/tier3/execution-lifecycle.md § The static default) are drawn: Execute, Review and Validate default back to Execute; an Architect or Plan problem found later defaults back to Architect or Plan respectively. The reviewer or validator that found the failure may override the default, but only upstream of it, and must record the reason — drawn here as a visually distinct edge kind, never the same line as a default, because a finder that could send work downstream of the default could wave work past its own gate.

The loop is bounded. attempt_start.budget carries four dimensions — turn_cap, token_cap, wallclock_cap_ms, iteration_cap — and all four are escalation triggers (docs/tier3/run-instrumentation-specification.md). iteration_cap is the one that stops a re-entry loop from running forever; past it the run escalates rather than re-entering again.
